2. 키 없이 Bedrock을 부르는 방법: Lambda 중계

방식: 앱은 Lambda Function URL로 JSON만 보낸다. Lambda는 자신의 실행 역할(IAM Role)로 Bedrock을 호출한다. 자격 증명이 Lambda 안에만 있어서 앱 코드와 GitHub 어디에도 키가 없다.

  1. 앱이 POST {LAMBDA_URL}/chat에 {system, messages, tools}를 보낸다.
  2. Lambda가 모델 ID(global.openai.gpt-6-luna)와 maxTokens를 서버 값으로 덮어쓰고 ConverseCommand를 호출한다.
  3. Lambda가 Bedrock 응답(텍스트 또는 toolUse)을 그대로 앱에 돌려준다. 에이전트 루프는 앱이 돌린다.

공개 저장소에 두지 않을 것: Lambda URL은 .env에 넣고 .gitignore에 올린다(EXPO_PUBLIC_API_URL). 팀원에게는 따로 공유한다. URL은 비밀번호가 아니라서 앱을 풀면 나오지만, 저장소에서 검색되지는 않는다. 커밋 전 검사로 gitleaks를 pre-commit 훅에 건다.

Lambda 실행 역할 권한

{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["bedrock:InvokeModel"],
    "Resource": [
      "arn:aws:bedrock:ap-northeast-2:<ACCOUNT_ID>:inference-profile/global.openai.gpt-6-luna",
      "arn:aws:bedrock:::foundation-model/openai.gpt-6-luna"
    ]
  }]
}

Lambda 코드 (Node.js, 약 25줄)

import { BedrockRuntimeClient, ConverseCommand } from "@aws-sdk/client-bedrock-runtime";
const client = new BedrockRuntimeClient({ region: "ap-northeast-2" });
const MODEL = "global.openai.gpt-6-luna";

export const handler = async (event) => {
  const path = event.rawPath;
  const body = JSON.parse(event.body ?? "{}");
  if ((event.body ?? "").length > 200_000) return json(413, { error: "too large" });

  if (path === "/chat") {
    const out = await client.send(new ConverseCommand({
      modelId: MODEL,                              // 앱이 보낸 값은 무시
      system: body.system,
      messages: body.messages,
      toolConfig: body.toolConfig,
      inferenceConfig: { maxTokens: 1024, temperature: 0 },
    }));
    return json(200, { output: out.output, stopReason: out.stopReason, usage: out.usage });
  }
  if (path === "/geocode") {
    const r = await fetch(`https://dapi.kakao.com/v2/local/geo/coord2regioncode.json?x=${+body.lng}&y=${+body.lat}`,
      { headers: { Authorization: `KakaoAK ${process.env.KAKAO_REST_KEY}` } });
    return json(r.status, await r.json());
  }
  return json(404, { error: "not found" });
};
const json = (statusCode, o) => ({ statusCode, headers: { "content-type": "application/json" }, body: JSON.stringify(o) });

설정: 런타임 nodejs24.x, 메모리 256MB, 타임아웃 60초, Function URL 인증 NONE, 예약 동시성 5. 예약 동시성이 동시 호출 수를 막아 주므로 누가 URL을 알아내도 비용이 급격히 늘지 않는다. Kakao 키는 Lambda 환경변수 KAKAO_REST_KEY에만 둔다.

3. 챗 한 번의 흐름 (에이전트 루프)

예: "나 저번에 강원도 갔던 게 며칠이었지?"

  1. 앱이 Converse를 호출한다. 입력은 시스템 프롬프트, 오늘 날짜, 뷰 스키마, 사용자 질문, 도구 2개 정의다.
  2. 모델이 query_sql을 호출한다. 예: SELECT id,name,start_date,end_date,nights,regions FROM v_trips WHERE regions LIKE '%강원%' ORDER BY start_date DESC LIMIT 5
  3. 앱이 SQL 가드(4장)를 거쳐 memory.db에 읽기 전용으로 실행하고 행을 돌려준다.
  4. 모델이 결과를 보고 더 필요하면 쿼리를 반복한다. 최대 6회다.
  5. 모델이 final_answer를 호출한다. 예: {"text":"10월 3일(금)~5일(일), 2박 3일이에요. 강릉 → 속초를 다녀왔어요.","cards":[{"type":"trip","id":"trip_2025_10_03"}]}
  6. 앱이 cards의 ID를 로컬 DB에서 다시 조회해 미니맵, 날짜, [재생] 버튼이 있는 근거 카드를 만든다. DB에 없는 ID는 버린다.

근거 카드의 내용은 모델이 쓴 글자가 아니라 DB 조회 결과다. 모델이 날짜를 지어내도 카드는 틀리지 않는다. PLAN.md 4장의 "도구 결과만 근거로 답한다" 원칙을 구조로 강제한 것이다.

4. 안전장치

위험대응
모델이 위험한 SQL을 생성① 에이전트는 memory.db를 PRAGMA query_only=ON인 별도 읽기 전용 연결로 연다. ② 한 문장, SELECT/WITH로 시작, ;·ATTACH·PRAGMA·load_extension 거부. ③ 뷰 이름 허용 목록 밖 테이블 참조 거부. ④ 바깥을 LIMIT 50으로 감싼다. ⑤ 실행 시간 2초 제한.
원시 좌표 유출points는 raw.db에 따로 둔다. 에이전트 연결은 이 파일을 열지 않는다. 뷰에는 lat/lng 컬럼이 없다.
집·회사 위치 노출집·회사 장소는 뷰에서 이름이 "집", "회사"로만 나온다. 주소와 좌표는 없다.
프롬프트 주입 (장소 이름 등 외부 문자열)모델이 할 수 있는 일이 읽기 전용 SQL과 답변 출력뿐이라 피해가 없다. 도구 결과 안의 문장은 지시가 아니라 데이터라고 시스템 프롬프트에 명시한다.
환각카드는 ID로 DB에서 재조립한다. 결과가 0행이면 "기록이 없어요"와 기록이 있는 기간(SELECT min/max)을 답하게 한다.
태그 정책 위반 (AI 태그)태그 호출은 별도 요청에서 JSON 스키마 enum + null로 강제한다. 앱이 tag_source='human' 행은 UPDATE하지 않는다.

5. SQLite 스키마

-- raw.db : 에이전트가 열지 않는다
CREATE TABLE points (
  id INTEGER PRIMARY KEY, t INTEGER NOT NULL,        -- unix 초
  lat REAL NOT NULL, lng REAL NOT NULL,
  accuracy REAL, speed REAL, source TEXT DEFAULT 'live' -- live | dummy
);
CREATE INDEX idx_points_t ON points(t);

-- memory.db
CREATE TABLE places (
  id TEXT PRIMARY KEY, name TEXT, lat REAL, lng REAL,   -- 좌표는 앱 전용
  poi_category TEXT, sido TEXT, sigungu TEXT, dong TEXT,
  tag TEXT CHECK (tag IN ('집','회사','밥집','커피','운동','쇼핑','관광') OR tag IS NULL),
  tag_source TEXT CHECK (tag_source IN ('human','ai') OR tag_source IS NULL),
  ai_reason TEXT
);
CREATE TABLE stays (
  id TEXT PRIMARY KEY, place_id TEXT NOT NULL REFERENCES places(id),
  start_t INTEGER NOT NULL, end_t INTEGER NOT NULL, day TEXT NOT NULL, trip_id TEXT
);
CREATE TABLE moves (
  id TEXT PRIMARY KEY, from_stay TEXT, to_stay TEXT,
  start_t INTEGER, end_t INTEGER, mode TEXT, distance_m INTEGER, path TEXT  -- path: 인코딩된 폴리라인
);
CREATE TABLE trips (
  id TEXT PRIMARY KEY, name TEXT, start_t INTEGER, end_t INTEGER,
  nights INTEGER, regions TEXT
);
CREATE TABLE days (day TEXT PRIMARY KEY, stay_count INTEGER, distance_m INTEGER, highlight_stay TEXT);

-- 에이전트가 보는 것은 뷰뿐 (좌표 없음, 집/회사 주소 없음)
CREATE VIEW v_places AS SELECT id, CASE WHEN tag IN ('집','회사') THEN tag ELSE name END AS name,
  poi_category, sido, sigungu, CASE WHEN tag IN ('집','회사') THEN NULL ELSE dong END AS dong, tag, tag_source FROM places;
CREATE VIEW v_stays AS SELECT s.id, s.day, datetime(s.start_t,'unixepoch','localtime') AS start_at,
  (s.end_t - s.start_t)/60 AS minutes, s.place_id, s.trip_id FROM stays s;
CREATE VIEW v_trips AS SELECT id, name, date(start_t,'unixepoch','localtime') AS start_date,
  date(end_t,'unixepoch','localtime') AS end_date, nights, regions FROM trips;
CREATE VIEW v_days AS SELECT day, stay_count, distance_m FROM days;

태그는 places에 있으므로 한 번 달면 그 장소의 과거·미래 방문 전체에 적용된다. 이 스키마는 PLAN.md 2장의 데이터 모델과 같다. 엔진 담당(B)이 첫날 이 DDL을 확정하면 앱(A)과 챗(C)이 목업 데이터로 병렬 작업할 수 있다.

7. 한계와 알아 둘 점

남용 위험: Function URL은 인증이 없어서 앱을 푼 사람이나 URL을 아는 사람은 누구나 /chat을 호출할 수 있다. 막는 장치는 모델·토큰 수 고정, 예약 동시성 5, Budgets 자동 차단이다. 사용자별 한도는 없다. 해커톤 데모에는 충분하다. URL이 새면 Lambda를 새로 만들어 URL을 바꾸고 앱 .env만 갱신한다.
위치 정보가 Lambda를 지난다: 질문과 SQL 결과 행(장소 이름, 시각)이 Lambda를 통과한다. 로그에 본문을 남기지 않는 것으로 막는다. /geocode는 좌표를 Kakao에 보낸다. 원시 점은 보내지 않고, 앱이 Stay로 만든 장소 중심점만 보낸다.
RN 스트리밍: React Native의 fetch는 응답 스트리밍을 기본 지원하지 않는다. 1차는 스트리밍 없이 Converse를 쓰고, 대기 중에는 "찾는 중…" 상태와 진행 단계(조회 중, 정리 중)를 보여준다.
미확인 항목: gpt-6-luna가 Converse의 toolConfig(도구 호출)를 지원하는지 아직 호출해 보지 않았다. 구현 첫날 이것부터 확인한다. 지원하지 않으면 JSON 출력 모드로 같은 루프를 만든다.

8. 팀이 정해야 할 것

① 지오코딩: Lambda가 Kakao 키를 갖고 있으므로 한국 POI 정확도가 높은 Kakao Local API를 그대로 쓴다. 더미 데이터는 생성기가 장소명을 이미 갖고 있어서 호출하지 않는다.

② 데이터 저장 위치: 이 설계는 "기기에만 저장"으로 확정한다. 이 결정으로 PLAN.md의 미결 항목 하나가 닫히고, US-26 화면의 문구도 "내 데이터는 내 폰에만 있고, 질문할 때 필요한 결과만 AI에 전달돼요"로 정해진다. 단점은 폰을 바꾸거나 앱을 지우면 기록이 사라지는 것이다. 백업은 이번 범위에서 뺀다.

③ 가입 없는 게스트로 갈지: 해커톤은 로그인 없이 간다.
