## 1. 본질: 이건 위치 추적 앱이 아니다

**하루는 "적지 않아도 쓰이는 일기"이자 "내 삶의 검색엔진"이다.**

사용자가 원하는 건 GPS 로그가 아니다. *"그때 나는 어디서 뭘 했지?"* 라는 질문에 대한 답이다.
원본 아이디어 다섯 줄은 결국 세 단계로 정리된다.

| 단계 | 원본 아이디어 | 본질 |
|---|---|---|
| 입력 | 위치를 계속 수집 | **노력 0의 기록.** 사용자는 아무것도 안 한다 |
| 의미화 | 언제 어디 → 무엇을 했는지 분류 | **좌표를 "기억 단위"로 바꾸는 엔진** (← 진짜 핵심 기술) |
| 회상 | 지도 재생 / LLM 챗 | 재생 = **감성**(다시 보기), 챗 = **효용**(다시 찾기) |

### 핵심 통찰 5가지

1. **원시 좌표는 가치가 0이다. 가치의 단위는 "머문 곳(Stay)"이다.**
   하루 수천 개 점은 "08:40–18:30 회사", "12:10–13:00 ○○식당" 같은 10여 개 Stay로 압축된다. 분류·재생·챗 모두 이 하나의 데이터 모델 위에서 돌아간다. **Stay 감지 품질 = 제품 품질.**

2. **사람은 "여행/사건" 단위로 기억한다.**
   "강원도 갔던 게 며칠이었지?" = *집을 떠나 → 강원도에 머물다 → 돌아온 구간*. 날짜 검색이 아니라 **Trip(외출·여행) 감지**와 **행정구역 계층(시/도 → 시/군/구 → 동)** 이 있어야 답할 수 있다.

3. **LLM은 데이터를 "읽는" 게 아니라 "조회"해야 한다.**
   좌표를 프롬프트에 몰아넣으면 틀린다. LLM은 질문을 구조화된 조회(도구 호출)로 바꾸는 역할만 맡고, 답에는 반드시 **근거 카드(지도 + 타임라인)** 를 붙인다. 기억 앱이 한 번 틀린 답을 내면 신뢰가 끝난다. 데이터가 없으면 "기록이 없어요"라고 말한다.

4. **기억 앱은 데이터가 쌓이기 전엔 쓸모가 없다 (콜드 스타트).**
   해커톤 데모에서 "저번에 강원도"를 물으려면 몇 달 치 데이터가 필요하다. → **더미 데이터 생성기로 해결한다** (5장 "더미 데이터 설계").
   핵심은 Stay를 손으로 만들지 않고 **노이즈가 섞인 원시 GPS Point를 생성**하는 것이다. 그래야 의미화 엔진이 진짜로 검증되고, 데모가 "미리 짜 놓은 화면"이 아니게 된다. 같은 데이터를 첫 실행 사용자의 "샘플로 둘러보기"에도 쓸 수 있다.

5. **위치는 가장 민감한 데이터다. 신뢰 자체가 기능이다.**
   집·회사 마스킹, 기간 단위 삭제, 기록 일시정지를 처음부터 넣는다.

## 2. 데이터 모델 (모든 기능의 바닥)

```
Point (lat, lng, t, accuracy, speed)          ← 수집 / 가져오기
  └─▶ Stay  (place_id, start, end)             ← 반경 ~100m, 10분 이상 머무름
  └─▶ Move  (start, end, path, mode)           ← Stay 사이 구간, 속도로 도보/차량/대중교통 추정
Place (좌표 클러스터, 이름, POI 카테고리, 행정구역 계층)
  └─ tag        : 정해진 태그 목록 중 하나 | null
  └─ tag_source : human | ai | null
  └─ ai_reason  : AI가 고른 근거, 또는 비워 둔 이유
Day   (하루 요약: Stay 목록, 이동 거리, 하이라이트)
Trip  (집 기준 생활권을 벗어난 구간: 출발~복귀, 방문 지역, 기간)
```

**장소 태그 (무엇을 했나):**

태그는 방문이 아니라 **장소(Place)에 붙는다.** "소원로 1가"를 한 번 `밥집`으로 태그하면 그곳의 과거·미래 방문 전체가 `밥집`이 된다.

- **태그 목록은 닫혀 있다**: `집` `회사` `밥집` `커피` `운동` `쇼핑` `관광`
- **사람이 태그한다**: 언제든 달고 바꿀 수 있다. 사람 태그가 최우선이고, AI는 사람 태그를 절대 덮어쓰지 않는다
- **AI가 태그한다**: 시간대, 체류 시간, 방문 빈도, 주변 POI를 보고 **목록 안에서 하나를 고르거나, 확신이 없으면 비워 둔다**
  - 목록 밖의 이름을 만들지 않는다 (출력은 enum + null)
  - `기타` 같은 버림 태그는 없다. 모르는 건 `null`로 남겨 사람에게 넘긴다
  - 고른 근거와 비워 둔 이유를 `ai_reason`에 남긴다
  - 집·회사는 규칙으로 먼저 추론한다 (야간 최빈 장소 = 집, 평일 주간 최빈 장소 = 회사)
- **사람의 확인**: AI가 단 태그에 "맞아요"를 누르면 `tag_source`가 `human`으로 바뀌어 고정된다
- **태그 정리 화면**: AI가 비워 둔 장소를 방문 많은 순으로 모아 보여주고 한 번에 태그하게 한다

## 3. 기능 정의

### P0 — 해커톤 필수

| # | 기능 | 설명 | 완료 기준 |
|---|---|---|---|
| F1 | **위치 수집** | 백그라운드 위치 수집. 움직일 땐 촘촘히, 머물 땐 드물게 (배터리) | 앱을 꺼도 하루치 점이 쌓인다 |
| F2 | **더미 데이터 생성기** | 페르소나 일과표 → 12개월 치 원시 Point 생성 (GPS 노이즈 포함) | 생성된 데이터가 엔진을 거쳐 기대한 Stay/Trip으로 복원된다 |
| F3 | **의미화 엔진** | Visit → Place(역지오코딩) → 태그 → Day/Trip | 하루가 10–20개 Stay로 깔끔하게 나온다 |
| F3-1 | **장소 태그** | 정해진 태그 목록 안에서 사람이 달거나 AI가 하나를 고른다. AI는 확신이 없으면 비워 둔다 | AI가 목록 밖 태그를 내지 않고, 사람 태그를 덮어쓰지 않는다 |
| F4 | **하루 타임라인** | 날짜 선택 → 세로 타임라인 + 지도 | "오늘 뭐 했지"가 한눈에 보인다 |
| F5 | **지도 재생** | 날짜/기간/Trip 선택 → 점이 시간 순으로 이동. Stay에서 멈추고 라벨 표시. 배속 조절 | 강원도 여행 3일이 30초 영상처럼 흐른다 |
| F6 | **기억 챗** | 자연어 질문 → 도구 호출 → 근거 카드와 함께 답변. 카드를 누르면 그 날 / 그 Trip 재생 | 아래 질문 5개에 정확히 답한다 |

### P1 — 시간이 남으면 (리텐션 장치)

회상은 가끔 필요하다. 매일 앱을 열 이유가 따로 있어야 한다.

- **오늘의 하루 카드**: 밤 10시 푸시 알림 "오늘 4곳, 8.2km". 카드 한 장 + 재생 버튼
- **1년 전 오늘**: "작년 오늘 당신은 속초에 있었어요"
- **자동 여행 앨범**: Trip이 끝나면 요약 페이지 자동 생성

### P2 — 이후

- 사진 연동 (EXIF 시간·위치를 Stay에 매칭해서 기억에 사진을 붙인다)
- 재생 영상 내보내기 (공유용, 자연스러운 바이럴)
- 소비 내역/캘린더 연동으로 "무엇을 했나" 정밀화
- Google 타임라인 내보내기(JSON) 가져오기: 실사용자의 과거 데이터 확보 수단

## 4. 기억 챗 설계

### 질문 유형 → 필요한 조회

| 질문 예시 | 유형 | 필요한 데이터 / 도구 |
|---|---|---|
| "저번에 강원도 갔던 게 며칠이었지?" | 여행 회상 | `find_trips(region="강원도")` |
| "작년 크리스마스에 뭐 했어?" | 특정 날 회상 | `get_day_summary(date)` |
| "성수동에서 갔던 그 파스타집 어디였지?" | 장소 찾기 | `search_places(area, category)` |
| "지난달 커피 몇 번 마셨어?" | 집계 | `stats(tag="커피", range)` (태그 없는 방문 수도 함께 알린다) |
| "요즘 운동 얼마나 했어?" | 패턴 | `stats(tag="운동", range, group_by="week")` |

### 답변 원칙

1. LLM은 **도구 결과만** 근거로 답한다. 추측 금지
2. 모든 답에 **근거 카드**: 날짜 · 장소 · 미니맵 · [재생] 버튼
3. 결과가 없거나 애매하면 되묻거나 "기록이 없어요"
4. "저번에", "그 파스타집"처럼 모호한 표현은 최근순 후보를 보여주고 고르게 한다

## 5. 해커톤 실행안

### 데모 시나리오 (3분)

1. 12개월 치 더미 데이터가 들어 있는 상태에서 시작한다 (페르소나 "지현"의 삶)
2. 오늘 탭: 오늘 하루 타임라인. 오늘만큼은 실제 폰으로 실시간 수집해서 해커톤 장소에 와 있는 것을 보여준다
3. 챗: **"나 저번에 강원도 갔던 게 며칠이었지?"**
   → "10월 3일(금)–5일(일), 2박 3일이에요. 강릉 → 속초를 다녀왔어요." + 근거 카드
4. 카드 [재생]을 누른다 → 지도 위에서 서울 → 강릉 → 속초 → 서울이 흐른다 (감탄 포인트)

### 더미 데이터 설계

**원칙: Stay가 아니라 원시 Point를 만든다.** 생성기 → 엔진 → Stay/Trip 순서로 흘러야 엔진이 검증된다. 생성 때 쓴 일과표가 곧 정답지가 된다.

| 요소 | 내용 |
|---|---|
| 기간 | 오늘 기준 과거 12개월 (2025-11 ~ 2026-11). "작년 크리스마스" 질문이 성립하려면 2025-12-25가 들어가야 한다 |
| 페르소나 | 서울 거주 직장인 1명 (집: 마포, 회사: 성수 같은 실제 동네) |
| 평일 루틴 | 집 → 출근 이동 → 회사 → 점심 식당(매일 다른 곳) → 회사 → 퇴근. 주 2회 저녁 헬스장 |
| 주말 | 카페, 쇼핑, 친구 약속. 장소는 실제 POI 좌표 풀에서 고른다 |
| 여행 (챗 데모용) | **강원도 2박 3일** (서울 → 강릉 → 속초 → 서울), 부산 1박 2일, 당일치기 1회. 날짜는 데모 대본에 맞춰 고정 |
| 데모 질문용 장면 | 성수동 파스타집 방문, 2025-12-25 크리스마스 일정, 월별 카페 방문 횟수 차이 |
| 현실감 | 이동 중 10–30초, 머무는 중 2–5분 간격 / 좌표 노이즈 ±15m / 가끔 100m 이상 튀는 점 / 지하철 구간 신호 끊김 / `accuracy`, `speed` 필드 |
| 형식 | 앱의 실제 수집 포맷과 같은 Point 스키마로 저장 → 실데이터와 같은 경로로 처리 |

**정답지 활용**: 생성기가 일과표(의도한 Stay/Trip 목록)도 같이 내보내면, 엔진 출력과 비교해서 Stay 감지 정확도를 숫자로 볼 수 있다. 이 숫자를 발표 자료에 넣을 수 있다.

**주의**: 데모 질문과 더미 데이터는 함께 설계한다. 대본에 있는 질문 하나하나에 정답이 되는 장면이 데이터 안에 있어야 한다.

### 3인 역할 분담 (제안)

| 담당 | 범위 |
|---|---|
| A · 앱 | 수집(F1), 타임라인 UI(F4), 지도 재생(F5) |
| B · 엔진 | 더미 데이터 생성기(F2), Stay/Trip 감지, 역지오코딩, 활동 분류(F3) |
| C · 챗 | LLM 에이전트, 도구 정의, 근거 카드 응답 포맷(F6) |

**인터페이스 계약을 먼저 고정한다**: B가 2장의 Stay/Trip 스키마를 첫날 확정하면 A와 C는 목업 데이터로 바로 병렬 개발할 수 있다.

### 기술 후보 (확정 아님)

- 앱: Expo(React Native) + `expo-location` / `expo-task-manager` (백그라운드 수집)
- LLM: Amazon Bedrock (Claude) + tool use
- 지오코딩/POI: **한국 장소·행정구역은 Kakao Local API가 정확도 면에서 유리.** 지도 표시는 Amazon Location Service나 Mapbox / Kakao Map
- 저장: 해커톤 규모면 Postgres(PostGIS) 하나면 충분

### 만들지 않을 것

회원가입·소셜 기능, ML 기반 분류 모델, 완벽한 배터리 최적화, 멀티 디바이스 동기화
